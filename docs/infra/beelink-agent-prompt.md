### 1. Найди существующий вход и используй его

Определи, каким VS Code и профилем я пользуюсь. Найди установленное расширение Microsoft Remote - SSH (ms-vscode-remote.remote-ssh), включая случай, когда команда code отсутствует в PATH. Проверь пользовательские и профильные settings.json на параметр remote.SSH.configFile. Если он пуст, начни с ~/.ssh/config; учти Include, нестандартный порт, имя пользователя, IdentityFile и ProxyJump. Смотри только относящиеся к задаче поля; содержимое ключей и полные настройки в отчёт не выводи. Сверь существующие алиасы через ssh -G. Расширение на Mac само по себе ещё не подтверждает работающий sshd на Beelink.

Для определения устройства используй известный алиас, имя mDNS, сведения DHCP домашнего роутера или адрес с локального экрана. Сверь, что это именно Beelink. При первом входе сравни ED25519 fingerprint с выводом sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub на консоли устройства. При смене известного ключа выясни причину. Войди обычным пользователем, проверь hostname, ОС и sudo. Если SSH уже работает, сохрани этот вход до полной проверки нового. Если на чистой Ubuntu sshd или ключ ещё не настроены и другого канала управления нет, дай мне один короткий блок команд для физической консоли: установить openssh-server, включить SSH, показать LAN-адрес и отпечаток, добавить согласованный публичный ключ Mac текущему пользователю с правами 700/600. Объясни, как передать .pub локально. Дождись результата и продолжай сам. Пароль sudo, MFA и passphrase владелец вводит в соответствующем приложении.

### 2. Добейся работающего доступа извне

Сначала испытай Tailscale между MacBook и Beelink с обычным OpenSSH по ключу. Проверь существующий tailnet, его владельца, коммерческий тариф, macOS-клиент и ограничения действующей политики. Повторно используй подходящие настройки. Перед новым платным обязательством сообщи сумму и получи согласие. Вход через браузер/MFA передай мне, когда понадобится. Для новой связи ограничь доступ с моего устройства к TCP/22 Beelink. Сохрани существующие VPN и LAN-вход; правила SSH, grants и firewall меняй адресно. Учитывай IPv6. Публичный порт на роутере, exit node и маршрутизация домашних подсетей этому проекту не требуются.

Создай отдельный постоянный SSH-алиас, например beelink-remote, в конфиге, который действительно использует Remote - SSH. Используй стабильное имя tailnet либо его IPv4, обычного пользователя и подходящий ключ. Сохрани остальные Host/Include и резервную копию изменяемых настроек. До отключения парольного входа проверь отдельное подключение по ключу и доступ к локальной консоли. На чистой машине настрой автозапуск tailscaled и OpenSSH с учётом фактически используемых service/socket units. Проверь последствия работы Amnezia одновременно с Tailscale: DNS, default route, IPv4/IPv6, доступ SSH. Существующий Timeweb — резерв при подтверждённой проблеме; изменение его конфигурации согласуй отдельно.

**Проверь снаружи до перехода к инструментам разработки.** Попроси меня переключить Mac на мобильную точку доступа, если сам этого сделать не можешь. Убедись, что домашний LAN недоступен с Mac, затем открой новое соединение по алиасу с отключённым SSH multiplexing и выполни hostname и whoami. Тем же алиасом открой новое окно VS Code Remote - SSH, открой домашний рабочий каталог Beelink и проверь hostname во встроенном терминале. Создай короткую проверочную задачу в tmux, разорви соединение, подключись вновь и проверь, что задача продолжалась. Проверь доступ после перезагрузки Beelink в согласованный момент, пока я рядом с консолью; учитывай возможный запрос разблокировки диска при загрузке. Оставь мне точную команду SSH, имя узла для VS Code и способ восстановления через LAN/консоль. Если внешнюю сеть или reboot проверить пока нельзя, перечисли конкретно, что уже работает и какой тест остался.

### 3. Подготовь постоянный agent host

После проверки удалённого управления сними модель, CPU, RAM/swap, диски/SMART, свободное место, Ethernet, время/NTP и режим сна. Настрой согласованный 24/7 режим без засыпания. Проверь BIOS auto power-on после восстановления питания; для действия в BIOS дай мне инструкцию для обнаруженной модели. Нужные обновления и перезагрузки планируй с сохранением проверенного канала.

Настрой Git, tmux и версии инструментов, требуемые приватным проектом. Клонируй его с авторизованным доступом владельца, рабочие ключи выдавай по назначению. Для Codex и Claude проверь вход и поддерживаемый запуск на самом Beelink, существующие подписки и доступность сервисов. Проверь, что процесс реально остаётся на Beelink после закрытия Mac. Docker ставь при подтверждённой зависимости. На каждого агента выдели отдельные branch/worktree, temp-каталог и порты. Тяжёлый FULL и CI предусмотрены на внешних runners. Работа с production, смена DNS, миграция staging, запуск боевых S3-задач и выключение Hetzner находятся за пределами этого поручения.

Прогони ступени 1/2/3/4 агентов на согласованных тестовых задачах. Запиши RSS, MemAvailable, swap-in/out, CPU, I/O и отзывчивость редактора на каждой ступени, останови увеличение нагрузки при деградации, укажи подтверждённый предел. Организуй проверку стабильности ≥24 часов с отметками начала/конца, uptime и обрывами. Согласуй российское место зашифрованного хранения уникальных локальных данных, проверь восстановление тестового файла. Результат по SSH передай сразу, суточную приёмку закрой отдельно по факту.

Пушь документацию в отдельной ветке, открой PR; после merge проверь живую страницу. В публичном GitHub оставляй только обезличенный результат. Адреса дома и tailnet, персональные имена, ключи, токены и сырые сетевые журналы остаются у владельца.
