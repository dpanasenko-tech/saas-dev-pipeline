# Поручение Codex в окне VS Code Remote‑SSH на Beelink

Ты работаешь в уже открытом удалённом окне VS Code. MacBook — клиент, Beelink с Ubuntu — хост. VS Code и Codex уже установлены, текущее SSH-подключение работает. Сначала подготовь на Beelink два checkout, затем настрой **вариант A — Tailscale с обычным OpenSSH**. Цель — открывать Beelink с MacBook из другой сети. Действующий LAN-сеанс оставь открытым для проверки и отката.

1. **Скачай оба проекта на Beelink.** Проверь в терминале hostname, uname и whoami. От имени обычного пользователя клонируй в ~/projects репозитории https://github.com/dpanasenko-tech/saas-dev-pipeline и https://github.com/dpanasenko-tech/ai-mp-manager. Если checkout уже есть, проверь origin, ветку и состояние и используй его, сохранив локальные изменения. Для приватного продукта используй уже настроенный GitHub-доступ. Если доступа нет, предложи владельцу интерактивный вход в GitHub на Beelink; токен и приватный ключ в чат не запрашивай. Подтверди путь и HEAD каждого checkout. Изучи docs/infra/architecture.md и docs/infra/beelink-ssh.md в первом проекте. Продукт достаточно склонировать.
2. **Настрой Beelink.** Проверь Ubuntu, состояние tailscale/tailscaled, существующий tailnet, работающий SSH и firewall. Установи недостающий клиент Tailscale из официального источника для обнаруженной версии Ubuntu, включи автозапуск tailscaled. Для нового подключения используй обычный OpenSSH через tailnet, без exit node и subnet routes, с сохранением текущих DNS и маршрутов. Если узел уже зарегистрирован, проверь его настройки перед любым изменением. Владелец выполняет браузерный вход/MFA. До подключения платного плана согласуй стоимость. Сохрани LAN-доступ и настройки Amnezia. В общем tailnet учитывай существующие grants; доступ с Mac к TCP-порту работающего sshd на Beelink ограничь адресно. Проверь состояние службы, tailnet-адрес и отпечаток используемого SSH host key.
3. **Подключи MacBook.** Из удалённого окна ты управляешь Beelink. Для действий в локальном контексте Mac дай владельцу короткую последовательность: подключить Tailscale к тому же tailnet, проверить узел, добавить beelink-remote рядом с рабочим LAN-алиасом в фактическом SSH-конфиге VS Code. Подготовь готовый Host-блок с проверенными HostName, User и Port. Для IdentityFile используй тот же рабочий ключ на Mac; если его путь тебе неизвестен, объясни, как взять его из локального алиаса. Сверь отпечаток при первом входе. Проверь новую сессию по ключу, оставив старую открытой.
4. **Докажи внешний доступ.** Попроси владельца переключить Mac на мобильную точку доступа и открыть новое подключение к beelink-remote в VS Code. В новом терминале проверь hostname и whoami. При ошибке проверь tailnet обоих устройств, grants, firewall, порт sshd и маршрут при включённой Amnezia. Переход на Timeweb находится вне этого поручения. Если владельца сейчас нет у Mac, зафиксируй отдельно готовность сервера и ожидающий внешний тест.
5. **Передай результат.** Сообщи владельцу пути обоих checkout, рабочую команду SSH, имя узла для VS Code и результат проверки из внешней сети. В PR публичного проекта обнови строку «Приватный доступ / agent host» в docs/infra/acceptance-report.md только подтверждёнными фактами. Адреса, имена устройств и сырые журналы оставь в приватной переписке. Если проверен только SSH, сохрани открытыми суточную приёмку и нагрузочные испытания agent host.
