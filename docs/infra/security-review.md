# Данные и права доступа

| Принципал | Разрешённый доступ | Граница |
|---|---|---|
| Разработчик на Beelink | Код, собственные worktrees, тестовые данные | Prod credentials хранятся у deploy/backup-сервисов |
| PR runner | Чтение кода, создание временных БД, запись обезличенного evidence | Изолировать сеть от БД приложения, отдельный доверенный publisher для registry |
| Staging deploy / workers | Только staging manifest, сеть, БД, тестовые кабинеты | Отдельные ключи API, ограничения уведомлений и расписания |
| Production deploy | Проверенный release manifest, pull registry, ограниченная операция deploy | Prod DB credentials доступны приложению по необходимости, release-агент их не получает |
| Backup / restore | Доступ по окружению, шифрование на клиенте, российский S3 | Recovery keys у владельца вне бакета; приватные журналы и тренировка в РФ |
| Timeweb relay | Административный канал разработки при выборе резерва | Весь трафик prod/staging и backup идёт напрямую в разрешённом контуре |

Синтетические фикстуры допускаются в CI. Кабинеты с реальными заказами, журналы с идентификаторами, WAL, файлы пользователей и дампы остаются в российском контуре. До копирования классифицировать существующий staging. В публичном репозитории сохранять только очищенные шаблоны и агрегаты. Перед ротацией административного доступа проверить альтернативный ключ и консоль восстановления. Ротацию выполнять отдельно в согласованное окно.
